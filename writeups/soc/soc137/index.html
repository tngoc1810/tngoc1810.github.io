SOC137 - Malicious File Download Attempt

Checking a malicious document download alert for NicolasPRD: the file assessment, the recorded block action and the available evidence for delivery or execution.

2. Initial Assessment & Hypothesis

I used the filename, document type and recorded action to choose the first checks:

  • Suspicious Filename & Extension: The filename uses the keyword "Invoice," which is a common social engineering tactic designed to trigger urgency or curiosity in users. Furthermore, the .docm extension (Word Macro-Enabled Document) is frequently abused by attackers to embed malicious VBA scripts. Once opened, these scripts can execute silently to download secondary payloads to the victim's machine.
  • Defense Action: The device action is logged as Blocked, indicating that the perimeter defense system likely intercepted the download attempt.
Investigation Goal: Despite the "Blocked" status, a deep-dive investigation is necessary to verify two critical points:
  1. Is the file genuinely malicious (True Positive), or is this a false alarm?
  2. Was the download attempt truly and successfully blocked at the network level?

Threat Intelligence & Malware Analysis

I checked the file hash in VirusTotal and reviewed the Joe Sandbox report.

VirusTotal recorded 40 detections from 64 vendors. Its tags referenced malicious macros, PowerShell activity and evasion behavior.

Joe Sandbox classified the file as malicious. The report showed obfuscated VBA commands and PowerShell child activity after opening the document and enabling content, consistent with a dropper.

The file-level evidence supports a true-positive assessment for a malicious document. It does not establish execution on NicolasPRD.

Log Management Analysis

I then checked whether NicolasPRD received or executed the document, rather than carrying the sandbox result over to the endpoint.

I searched Log Management by source IP (172.16.17.37), hostname and the alert window. I found no successful connection or file-transfer event.

The available network search did not show a successful transfer. This is consistent with the recorded block action, but an empty result alone does not prove that delivery was impossible.

Endpoint Analysis & C2 Check

The EDR view for NicolasPRD showed no matching .docm file, execution event or unusual child process in the reviewed scope. I found no endpoint evidence of execution there.

The reviewed network logs also contained no matching C2 or beaconing activity from NicolasPRD. This supports the blocked-attempt assessment within that search scope; it is not a guarantee that the endpoint is free of every compromise.

Analyst Note & Verdict

SOC137 (EventID: 76) concerns a malicious .docm download attempt on NicolasPRD. The recorded action is Blocked. The network and EDR views reviewed here show no successful delivery, execution or matching C2 activity. I retained the true-positive, blocked-attempt disposition, with that conclusion limited to the available telemetry and time window.

Final Verdict: True Positive.
Action: Close as a blocked attempt within the reviewed scope. Reopen if new evidence shows delivery, execution or related C2 activity.

Lessons Learned & Takeaways

  • The SIEM action was blocked, but I still checked network and EDR telemetry before closing the alert. In this case, neither source showed successful delivery or execution.
  • A malicious-file verdict and an endpoint-compromise verdict answer different questions. Here, the available endpoint and network records supported a blocked attempt; I found no evidence of execution in the reviewed window.
